# 多屏互动推送协议与证据

## 来源及适用范围

参考 Aerial 项目的 tools/tcast-push.py、docs/tcast-protocol.md、docs/devices/tcl-mt5879-cn.md。它们描述的是从 TCL 多屏互动手机协议整理出的兼容实现，不是 TCL 承诺稳定的公开 API。

证据等级：

| 内容 | 当前证据 |
|---|---|
| 电脑经 TCP 6553 发起多屏互动安装，电视确认后成功 | 已在用户雷鸟 S535D / Android 9 / V206 上多次实际使用 |
| 电脑本机 HTTP + 已授权 ADB reverse 下载 | 同一设备已实测；不是手机端实现 |
| Android 手机实现相同控制协议 | JVM/回环模拟通过；用户报告此前安装包正常使用，未附逐项设备记录；0.2.1 待回归 |
| 手机局域网 HTTP 地址被电视接受 | 用户报告旧包推送可用；未提供本轮设备/固件信息，不泛化到所有型号；部分上游固件有拒绝记录 |
| 手机 ADB 客户端建立完整 reverse 数据通道 | 尚未实现、尚未实测 |
| 其他品牌/型号均可用 | 没有证据，不得宣传 |

## TCP 帧

端口：6553。每帧是：

```text
4 字节大端整数：UTF-8 payload 的字节数
随后恰好该长度的 UTF-8 payload
```

字段通常以 `>>` 分隔。实现必须处理拆包和粘包，限制帧大小，拒绝负数和异常长度。中文长度按 UTF-8 字节数计算，不按字符串字符数计算。分割时保留尾部空字段。

## 基础握手和心跳

已用过的明文请求：

```text
159>>1>>0
```

参考文档中的应答：`253>>1>>0`，还可能收到设备信息。手机端先验证应答和服务器行为，不把“TCP connect 成功”直接认作握手完成。

心跳请求：`150>>`，常见响应：`150>>YES`。上游 Python 工具约每 5 秒发送；补充资料描述约 20 秒无流量可能断链。实际阈值属于固件行为，不可宣称固定保证。等待电视同意时也需保持会话。

## 安装请求

参考格式：

```text
223>>INSTALL>>package>>label>>url>>2>>versionCode>>sizeMB>>appMd5>>signatureMd5>>icon>>apkPathMd5
```

- package、label、versionCode：从用户选择的 APK 解析。
- url：电视能访问的 APK 下载地址，不是手机的 content:// URI。
- 来源字段 `2` 在参考实现中表示手机本地 APK 推送。
- apkPathMd5：参考实现使用下载 URL 的 MD5，不是 APK 内容的 MD5，更不是认证凭据。
- appMd5、signatureMd5、icon 在参考工具中允许留空；不要擅自填入不明数据。
- sizeMB：参考 Python 脚本硬编码为 `20`。这只能证明该脚本在部分设备上这样能运行，不能证明所有固件忽略真实大小。0.1.0 实验版使用实际字节数除以 1,048,576 向上取整（MiB）；**单位/取整是待目标电视验证的假设**，不是已证实的协议要求。

字段中存在 `>>`、换行或不支持的编码时，必须拒绝或采用已经验证的编码方式，不直接拼接用户文本。非 ASCII 名称也要测试。

## 回执

常见安装确认消息：

```text
223>>INSTALL>>package>>label>>confirm_pending|denied|installing|installed>>apkPathMd5
```

常见进度消息：

```text
223>>PROGRESS>>package>>label>>stage>>percent>>apkPathMd5
```

参考实现中的 stage：

| stage | 含义 |
|---|---|
| 1 | 下载中 |
| 3 | 安装中 |
| 5 | 安装完成 |
| 2 | 失败 |

当前电脑链路以匹配包名的 `PROGRESS stage=5` 为安装成功依据。手机实现还应尽可能核对 URL 路径标识和当前会话，防止迟到回执。`INSTALL installed` 等其他消息不能不经验证就成为等价成功信号。

电视提示默认焦点可能在“拒绝”，UI 明确提示用户：**按右 → 选同意 → 按确认**。收到拒绝应立即终止任务，不自动再次弹窗。

## APK 下载是独立兼容问题

手机不能简单返回 `http://127.0.0.1:8765/...`：该地址在电视端指向电视自己，除非已经建立真实的 ADB reverse 等桥接。

上游 docs/tcast-protocol.md 有报告：部分设备拒绝局域网非标准端口 APK URL，电视甚至不发 HTTP 请求；同设备通过 ADB reverse 回环地址可用。此结论不能直接推广为“所有雷鸟都拒绝局域网 URL”，也不能忽略它并把手机直连当成已实现。

实现前必须独立验证：控制请求送达、电视是否同意、电视是否真的开始 HTTP 请求、传输是否完整、最后是否安装。这些证据分别记录。

## 非 MVP 指令与加密

补充文档还涉及加密握手、截图、遥控和远程 Intent。它们不属于本项目 MVP，不复制任意 Intent 或遥控能力作为隐藏功能。

先使用已知明文模式。如遇必须加密协商的固件，先明确标为不兼容并核对原始资料，不猜测算法、密钥、IV 或重复解密规则。上游加密参数也不是安全身份认证，不以此宣传安全配对。

## 回归用例

至少覆盖中文字段、UTF-8 长度、连续多帧、逐字节拆帧、尾部空字段、负数/超限长度、无效 UTF-8、未知指令、进度越界、其他包名回执、旧会话完成消息、超时、拒绝和 TCP 断开。安装阶段超时或断链没有最终回执时，提示“结果未知”，不要把可能仍在电视上继续的安装判成已取消。
