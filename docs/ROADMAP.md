## P0：优先验证可行性

目标：在开发完整 UI 前确认手机 APK 下载通道可用。

1. 经用户同意，在指定电视测试 6553 控制通道。
2. 验证手机局域网 HTTP 下载路径，包括电视是否实际发出请求，而不仅是手机端监听成功。
3. 在目标雷鸟上测试单个无害、用户明确选择的 APK，记录电视确认、下载、安装结果。
4. 若 LAN URL 被拒绝，区分固件过滤、网络隔离、接口选择和手机系统限制；不要直接归因于同一原因。
5. 必须转向 ADB 时，先完成手机授权和 reverse 数据流原型，再决定兼容模式产品设计。

**退出条件**：至少一种路径完整安装成功，或得到具体阻碍和可复核证据。未通过时不能宣称“手机免 ADB 推送已支持”。

## P1：Android 项目骨架与纯协议测试

- 核实稳定 SDK、Kotlin、Compose、Gradle 版本，初始化最小单模块项目。
- 实现帧编解码、消息类型和状态机的单元测试。
- 手动 IP 连接、SAF 选 APK、元信息展示、输入检查。
- 不做网络扫描、云端服务或电视系统设置修改。

**验收**：构建可复现、单测通过；打开 App 不自动连接或推送；错误地址/错误文件给出明确反馈。

## P2：单次推送闭环

- 只接入 P0 已验证的下载通道。
- 用户主动发起后，前台服务承载 TCP 与文件传输。
- 心跳、电视确认、下载、安装、取消、期限和终态完整贯通。
- 安装完成只根据匹配会话的真实回执展示。

**验收**：目标电视允许后安装成功；拒绝/不操作/断网/下载不可达/旧回执都不能误报成功。结束后端口、连接和服务无泄漏。

## P3：可靠性与最小发布

- App 切后台、屏幕关闭、旋转、进程重建、二次推送、Wi-Fi 变化测试。
- 大文件、重名文件、中文名称、不兼容 APK、签名/版本冲突的可解释失败。
- APK 缓存和会话资源清理、脱敏诊断导出。
- release 构建真机验收，记录手机型号、系统、电视型号、固件和测试边界。

**退出条件**：多轮安装及失败场景通过，没有临时服务常驻、静默重发或越权操作。

## 后续候选，不自动纳入 MVP

用户主动的设备发现、最近设备、批量队列、用户提供的下载链接、多固件协议适配。每项先有明确需求和兼容性证据，再增加。
