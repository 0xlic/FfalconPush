# FfalconPush

面向 Android 手机的雷鸟 / TCL 电视 APK 推送工具。用户在手机上选择 APK、连接自己的电视、发起推送，在电视「多屏互动」提示中确认后，由电视系统完成安装。

**当前版本：0.2.1，简洁图形界面与矢量雷鸟图标。用户已反馈此前安装包可正常使用；本次新版界面、覆盖升级和设备异常场景仍待真机回归。** 用户尚未提供手机/电视版本及逐项测试记录，不据此扩大固件兼容承诺。仅接入手机局域网 HTTP，暂不含 ADB reverse。

## 安装测试

- 本地构建安装包：`app/build/outputs/apk/release/app-release.apk`，或本轮本地产物 `artifacts/FfalconPush-0.2.1.apk`。安装到 **Android 8.0+ 手机**，不是电视。公开源码仓库不包含 APK、日志或设备资料，目前未发布 GitHub Release。
- 点击电视图形选择/输入电视地址，历史记录可选或删除；点击 APK 卡片选文件，已选文件可查看包名/版本/大小或更换；点击上箭头推送，传输时方形按钮取消。
- 主界面不显示应用名称、介绍、本机 IP、哈希或日志；按压回弹、流动光点、进度环和状态切换表达过程。电视同意提示、失败/未知结果保留必要短文字，不能用成功动画掩盖未知结果。
- 成功连接后，本机保存最近 8 台电视地址，重开默认选中最近地址。**恢复记录不自动联网或推送**，连接记录不参与备份或诊断分享。第三方许可与主动诊断分享收在电视选择面板内。
- 名称已更正为 `FfalconPush`，versionCode 为 4。保留原 applicationId、签名和连接记录路径；请直接覆盖安装，无需卸载。
- 本包为 `release` 构建、使用本机 debug 证书签名，仅供自行测试，不是正式发布签名。更新须使用相同证书并核对 versionCode，不要通过卸载已有应用来规避签名冲突。
- 操作步骤、失败定位与测试清单见 [手机安装测试](docs/TESTING.md)，实际检查证据见 [本轮验证](docs/IMPLEMENTATION.md)。

复现构建（JDK 17、Android SDK 36.1 / Build Tools 36.1.0）：

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk" # 按本机 SDK 路径修改
./gradlew :app:testDebugUnitTest :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease
```

输出：`app/build/outputs/apk/release/app-release.apk`。不要上传自己的签名密钥。

## 产品目标

- 在手机上完成推送，不要求用户每次使用电脑或命令行。
- 优先利用电视已有的「多屏互动」，不 root、不装电视端伴侣、不替换电视系统组件。
- 显示连接、等待电视同意、下载、安装和最终结果，不把“文件传完”当作“安装成功”。
- 不联网收集用户数据、不上传 APK 到第三方、不自动安装或更新其他应用。

首个目标设备是雷鸟 S535D（非 Pro），系统型号 `tcl_m7642`，Android 9，V206 固件。其他 TCL / 雷鸟型号按实测逐项增加兼容记录，不承诺所有型号通用。

## 用户流程

1. 手机与电视处于互通的局域网。
2. 输入电视 IP 或选择本机保存的最近记录；不做后台全网扫描。点击上箭头推送后才建立 TCP 6553 会话并验证握手。
3. 使用 Android 文件选择器选择一个完整 `.apk`，卡片显示应用名、版本和大小，点卡片查看真实包名或更换文件。
4. 根据已验证的兼容模式准备下载地址，用户明确点击“推送”。
5. 提示用户在电视上先按遥控器“右”选中“同意”，再按确认。
6. 显示电视返回的下载、安装状态；收到对应任务的安装完成回执才显示成功。
7. 成功、失败、取消或超时后，结束会话、停止临时服务并清理自己创建的临时文件。

## 关键技术边界

控制通道与 APK 下载通道是两回事：

```text
手机 --TCP 6553 安装请求--> 电视多屏互动
电视 --HTTP 下载 APK--> 指定的 APK 下载地址
电视 --协议状态回执--> 手机
```

已有电脑实测链路：

```text
电脑 HTTP 服务 127.0.0.1:临时端口
  ← 已授权 ADB reverse 通道
  ← 电视访问 http://127.0.0.1:电视端口/文件.apk
```

**不能把这个 127.0.0.1 地址直接照搬到手机 App。** 在电视发出的 HTTP 请求中，127.0.0.1 指的是电视本机。

手机端候选下载方式：

| 方式 | 状态 | 要求与风险 |
|---|---|---|
| 手机局域网 HTTP 服务，电视直接下载 | 用户报告旧包正常使用；新版及异常场景待回归 | 上游有部分固件拒绝局域网非标准端口 URL 的实测记录，必须先在目标电视验证 |
| 手机内嵌 ADB 客户端，建立 reverse 通道 | 待实现、待验证 | 电视需开启 ADB 并授权手机；所选客户端必须真正支持 reverse 数据转发，而不只是 shell |
| 用户主动提供的可访问下载链接 | 可选后续功能 | 校验可达性和包信息；不能为此默认上传本地 APK 到公网 |

**当前按用户要求先提供 LAN HTTP 实验包，再由用户在手机验证下载路径，之后才确定正式 MVP 的默认模式。** 如果直连被拒绝，不得继续把“无需 ADB 的本地文件推送”当作已成立的产品能力。手机内嵌 ADB 是兼容方案，不等于用户需要电脑，也不能绕过电视授权。

## 技术方向

- Kotlin、Jetpack Compose、协程；优先单个 `app` 模块，协议解析保持为可单测的纯 Kotlin 代码。
- 当前 minSdk 26、compileSdk 36.1、targetSdk 36；工具链与依赖固定版本，选择依据及 Android 局域网/前台服务限制见架构文档。
- 文件通过 Storage Access Framework 获取，复制到应用私有缓存后解析和发送；不申请“所有文件访问”。
- TCP I/O、文件复制、APK 解析和 HTTP 服务均不运行在主线程。
- 仅在用户主动开始传输时启动适配目标 Android 版本的短时前台服务，完成后退出；不添加开机自启或永久保活。
- 默认不依赖 ADB；若验证表明该固件必须使用 ADB 通道，应在 UI 中明确说明并获得授权，不静默升级权限。

## MVP 范围

包含：手动连接一台电视、选择单个 APK、解析元信息、下载可达性验证、电视确认提示、状态机、进度、取消、超时、可分享的脱敏诊断。

不包含：批量安装、应用商店、下载第三方 APK、手机已安装应用提取、后台扫描、远程控制、截图、卸载、系统设置修改、ADB 调试开关管理、split APK / APKS / XAPK / AAB 安装。
